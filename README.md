I'm a software engineer with **9+ years of professional experience** building modern web applications.

My strongest background is in **React, Next.js, TypeScript, frontend architecture, and performance**. Over the last few years, I've expanded further into full-stack engineering with **Node.js, PostgreSQL, Redis, APIs, authentication, background jobs, and application architecture**.

I also have **4 years of production Web3 experience**, working across multiple EVM networks and Solana on wallet-connected applications, NFT marketplace flows, account linking, smart contract interactions, and transaction synchronization.

Outside professional work, I use **Eastbase Studio** as a personal engineering lab for end-to-end product development, architecture experiments, and AI-assisted workflows.

## ⛓️ Web3 Experience

My Web3 work has primarily been at the **application and integration layer** — connecting polished product experiences to blockchain systems reliably.

- Built and maintained production dApps across **multiple EVM networks and Solana**
- Implemented **wallet authentication**, signing flows, and wallet/account linking
- Built **NFT marketplace** buy/sell flows and platform-fee integrations
- Worked with **Wagmi, Viem, RainbowKit, and ethers.js**
- Handled transaction lifecycle UX: pending, confirmation, failure, retries, and network switching
- Synchronized **on-chain state with backend/application state**
- Integrated smart contracts from the application side and worked with contract-driven business flows
- Designed frontend architecture for asynchronous, state-heavy Web3 experiences

> My main specialization is Web3 application engineering rather than deep Solidity/smart-contract development.

## 🧭 How I Work

<table>
<tr>
<td width="50%" valign="top">

### Engineering

- Start from system behavior and failure modes, not only implementation
- Keep architecture proportional to the product and scale
- Care deeply about frontend performance and interaction quality
- Design APIs, async flows, caching, and state transitions explicitly
- Prefer observable, reviewable production systems

</td>
<td width="50%" valign="top">

### Product & Delivery

- Translate requirements into clear technical boundaries
- Work comfortably in existing codebases and incremental migrations
- Ship end-to-end features instead of optimizing only one layer
- Use AI tools to accelerate research, implementation, review, and testing
- Keep final engineering decisions under human ownership

</td>
</tr>
</table>
